# OCR: распознавание текста номерных знаков

Этот документ описывает, как устроена и как была построена OCR-часть
системы: от первоначальной проблемы до текущей реализации.

## Исходная проблема

Постановка задачи и известные проблемы старого решения на RapidOCR
подробно описаны в `OCR_TASK.md`. Кратко: RapidOCR — general-purpose
OCR-движок, не заточенный под номерные знаки, и давал систематические
ошибки — терял крайние символы, путал похожие символы, добавлял лишние
символы от текстуры фона, нестабильно читал один и тот же номер на
разных кадрах.

Первоначальный план (см. `OCR_TASK.md`) предполагал полностью самописное
решение: посимвольная сегментация кропа номера (`CharacterSegmentor`) с
последующей классификацией каждого символа отдельной CNN
(`CharacterClassifier`), обученной с нуля на датасете отдельных символов.
От этого плана отказались в пользу дообучения готовой модели

## Изменение подхода

Вместо посимвольной сегментации и обучения классификатора с нуля было
решено использовать библиотеку `fast-plate-ocr` (обёртка над ONNX
Runtime, специализированная на распознавании номерных знаков целиком, без
сегментации на отдельные символы) и дообучить одну из её предобученных
моделей на собственном датасете.

Причины:

- Библиотека уже предоставляет предобученные модели, архитектуру,
  инструменты валидации датасета и обучения — не нужно писать и обучать
  классификатор с нуля.
- Модель классифицирует номер целиком (multi-head classifier: одна
  классификационная голова на позицию символа), что снимает проблему
  сегментации контурами, к которой изначально планировалось прибегнуть
  и которая сама по себе была источником потенциальных ошибок (слипшиеся
  символы, разрывы при плохом освещении).
- Экспорт в ONNX даёт лёгкий и кроссплатформенный рантайм, без
  зависимости от PyTorch/TensorFlow в проде.

## Выбор модели

Библиотека предоставляет несколько предобученных моделей. Изначально был
скачан `global-plates-mobile-vit-v2-model` (архитектура MobileViT). При
подготовке к дообучению выяснилось, что эта модель числится в
документации библиотеки как legacy — поддерживается только для
инференса и не рекомендована для дообучения.

Вместо неё выбрана модель `cct-s-v2-global-model` — рекомендуемая
библиотекой модель на архитектуре Compact Convolutional Transformer
(CCT): свёрточный токенизатор (несколько Conv2D-блоков с
MaxBlurPooling2D) плюс transformer-энкодер из 5 слоёв. Модель обучена на
номерах 65+ стран и поддерживает как распознавание текста, так и
(опционально) региона происхождения номера.

Конфигурация модели (`cct_s_v2_global_plate_config.yaml`):

- `max_plate_slots: 10` — максимальная длина номера.
- `alphabet` — цифры и заглавные латинские буквы, плюс паддинг-символ.
- `img_height: 64`, `img_width: 128`, `image_color_mode: rgb`.
- `plate_regions` — список из 65 стран для региональной классификационной
  головы.

## Датасет

Датасет собирается скриптом `ocr_model/build.py` из четырёх источников с
разными исходными форматами:

- **eu1** — уже готовые train/val/test-папки, метка в имени файла.
- **eu2, us2** — формат "картинка + txt с bbox и текстом" (end-to-end
  разметка), скрипт кропает номер по bbox с паддингом.
- **us3** — изображения плюс отдельный `groundtruth.csv` с меткой и
  штатом.

Все записи сводятся в единый `dataset.csv` с полями `image_path, text,
region, source, split`. На этом шаге метки валидируются (только символы
A-Z и 0-9, отсекается чёрный список тестовых меток вида SAMPLE/DEMO).

Итоговый размер датасета — 1813 записей: 843 европейских (источник eu1,
eu2) и 970 американских (источник us2, us3 — us3 дополнительно размечен
по штатам, от 1 до 35 записей на штат).

Собранный датасет визуально проверен скриптом `ocr_model/
inspect_dataset.py`, который сохраняет случайную выборку картинок с
подписями в `ocr_model/debug/` для ручного просмотра.

### Подготовка к обучению

`ocr_model/prepare_split.py` конвертирует `dataset.csv` в формат,
ожидаемый `fast-plate-ocr` (`image_path, plate_text`), и делит на
train/val (90/10) со стратификацией по региону, чтобы в обеих выборках
сохранялись пропорции eu/us из общего датасета. Номера длиннее
`max_plate_slots` символов отбрасываются.

Пути к изображениям в `train.csv`/`val.csv` записываются относительными
(относительно директории, где лежит сам csv-файл) — это требование
`fast-plate-ocr`, который резолвит пути конкатенацией директории
csv-файла с содержимым поля `image_path`, без обработки уже абсолютных
путей.

Дополнительно в csv записывается поле `plate_region`: `"United States"`
для американских записей (это значение уже есть в списке `plate_regions`
конфигурации модели) и `"Unknown"` для всех остальных — датасет не
содержит разметки по конкретным европейским странам, только по паре
регионов eu/us.

Итоговое разбиение: train — 1632 записи (759 eu, 873 us), val — 181
запись (84 eu, 97 us).

## Обучение

Обучение запускается через `ocr_model/train.py` — обёртку над CLI-командой
`fast-plate-ocr train`. Используются предобученные веса `cct_s_v2_global.
keras`, скачанные из релизов репозитория `fast-plate-ocr` (`.keras`-веса
для дообучения раздаются отдельно от `.onnx`, который библиотека
скачивает автоматически для инференса — `.onnx` для дообучения не
подходит).

### Региональная голова

Поскольку датасет не содержит честной разметки по странам (все
европейские номера размечены как "Unknown"), обучение на этих данных
без ограничений испортило бы то, что модель уже умела определять по
региону — она начала бы связывать реальные признаки европейских номеров
с меткой "Unknown". Чтобы этого избежать, вес функции потерь для
региональной головы (`--region-loss-weight`) выставлен в 0 — эта часть
модели не получает градиент и её веса не изменяются в процессе
дообучения. Обучается только голова распознавания текста номера
(`--plate-loss-weight`).

### Параметры и результат

Обучение проводилось на CPU (GPU-ускорение через Metal не удалось
задействовать из-за несовместимости версий `tensorflow-metal` с
установленным TensorFlow; на объёме данных проекта время обучения на
CPU оказалось приемлемым — порядка 30-60 секунд на эпоху).

Обучение остановилось автоматически по early stopping на 46-й эпохе
(из 70 заданных, patience — 15 эпох без улучшения `val_plate_acc`).

Результат на отложенной выборке (`val.csv`), измеренный через
`fast-plate-ocr valid`:

| Метрика | До дообучения | После дообучения |
|---|---|---|
| plate_acc (полное совпадение номера) | 87.85% | 94.48% |
| plate_char_acc (посимвольная точность) | 98.12% | 98.84% |
| plate_len_acc (точность определения длины) | 96.69% | 98.34% |

## Экспорт и интеграция

Лучший чекпоинт обучения (`best.keras`) экспортирован в ONNX командой
`fast-plate-ocr export`. Экспорт включает автоматическую валидацию:
сверяет, что предсказания ONNX-модели совпадают с предсказаниями
исходной Keras-модели.

Итоговые артефакты вынесены в `weights/` в корне проекта:

- `ocr_best.keras` — веса в исходном формате, для возможного дальнейшего
  дообучения.
- `ocr_best.onnx` — веса для инференса в приложении (5.3 МБ против 17.6
  МБ у `.keras`).
- `ocr_plate_config.yaml` — конфигурация модели, необходимая для
  инференса (не экспортируется автоматически вместе с ONNX-файлом,
  скопирована отдельно).

`app/ocr_engine.py` использует класс `LicensePlateRecognizer` из
`fast-plate-ocr` с этими файлами. Публичный интерфейс класса `PlateReader`
(`read_plate(image) -> (text, confidence_level)`) сохранён без изменений
по сравнению с версией на RapidOCR, поэтому остальной код приложения
(`image_processor.py`, `video_processor.py`, `bot.py`) не потребовал
модификаций.

Препроцессор кропа (`PlatePreprocessor` — CLAHE, sharpen, upscale),
использовавшийся с RapidOCR, в новой реализации не применяется:
`LicensePlateRecognizer` выполняет собственный ресайз изображения под
входной размер модели, а первые тесты на прежде проблемных случаях
показали корректное распознавание без дополнительной обработки. Вопрос
о необходимости препроцессинга остаётся открытым и может быть
пересмотрен при появлении новых проблемных случаев.

## Не перенесённая функциональность

Определение региона (страны) номера технически доступно в модели, но не
используется в приложении и не тестировалось: датасет для дообучения не
содержал honest-разметки по странам, а веса региональной головы не
изменялись в процессе дообучения (см. раздел "Региональная голова" выше).
