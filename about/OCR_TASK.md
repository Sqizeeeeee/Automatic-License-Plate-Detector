# Задача: Улучшение OCR для распознавания номерных знаков

## Контекст

Текущий пайплайн системы:
```
Фото/видео → YOLOv8s (детектор) → deskew → PlatePreprocessor → RapidOCR → фильтрация чанков → результат
```

Детектор работает хорошо. Узкое место — OCR часть. RapidOCR (обёртка над PaddleOCR) является general-purpose движком, не заточенным под номерные знаки, и имеет системные проблемы которые нельзя решить только тюнингом параметров.

---

## Известные проблемы текущего OCR

| Проблема | Пример | Причина |
|----------|--------|---------|
| Потеря первого символа | G402205 → 402205 | Узкий чанк отсекается height-фильтром |
| Путаница похожих символов | MAW323 → MAW33 | Ошибка recognition модели |
| Галлюцинации символов | P033086 → P0G33086 | Лишний чанк от текстуры металла/декора |
| Нестабильность на видео | CZF9968 читается по-разному на разных кадрах | Низкий confidence при граничных случаях |
| Иероглифы | 桂703 на металлическом фоне | RapidOCR обучен на китайских текстах |

---

## Цель

Заменить RapidOCR на собственный OCR-модуль заточенный под номерные знаки, который:

1. Не галлюцинирует символы которых нет на номере
2. Стабильно читает один и тот же номер на разных кадрах
3. Не теряет первые/последние символы
4. Не путает похожие символы (0/O, 1/I, 2/Z, 5/S, 8/B и т.д.) на уровне ниже текущего

---

## Предлагаемый подход: посимвольная сегментация + CNN классификатор

### Архитектура

```
кроп номера
    ↓
PlatePreprocessor (уже есть: CLAHE + sharpen + upscale)
    ↓
бинаризация + морфология
    ↓
CharacterSegmentor (новый класс)
    ↓
список кропов отдельных символов [img_A, img_W, img_3, ...]
    ↓
CharacterClassifier (новый класс, CNN)
    ↓
список предсказаний [('A', 0.98), ('W', 0.95), ('3', 0.99), ...]
    ↓
сборка строки + взвешенный confidence
```

### Почему это лучше

- Каждый символ классифицируется независимо — нет проблемы "чанков" и их фильтрации
- 36 классов (A-Z + 0-9) против general-purpose OCR — значительно проще задача
- Полный контроль над тем что именно классифицируется
- Нет галлюцинаций целых слов — если символ не найден сегментором, он не появится в результате
- Детерминированный результат — нет случайности как в beam search

## Шаг 1: CharacterSegmentor

**Файл:** `app/character_segmentor.py`

**Вход:** BGR изображение кропа номера (после PlatePreprocessor)

**Выход:** список кропов символов отсортированных слева направо `[np.ndarray, ...]`

**Алгоритм:**
1. Перевести в grayscale
2. Otsu бинаризация → инвертировать (символы белые, фон чёрный)
3. Морфологическая дилатация (соединить разорванные части символов)
4. Найти контуры (`cv2.findContours`)
5. Фильтровать контуры по:
   - высоте (не меньше 40% от высоты изображения)
   - соотношению сторон (символ не может быть шире чем высокий — ratio < 1.5)
   - площади (отсекать шум)
6. Сортировать контуры по x-координате (слева направо)
7. Вырезать каждый символ с небольшим паддингом, ресайзить до 32x32

**Сложные случаи которые нужно учесть:**
- Дефис/пробел в номере (M-AW323) — не является символом, нужно игнорировать
- Слипшиеся символы — если контур слишком широкий, разбить вертикальной проекцией
- Символы с отверстиями (0, 8, B) — `RETR_EXTERNAL` решает эту проблему

## Шаг 2: Датасет для CNN

**Что нужно:** изображения отдельных символов номерных знаков с метками (A-Z, 0-9)

**Источники:**
- [Chars74K dataset](http://www.ee.surrey.ac.uk/CVSSP/demos/chars74k/) — символы в реальных условиях
- [EMNIST](https://www.nist.gov/itl/products-and-services/emnist-dataset) — рукописные + печатные символы
- [License Plate Characters dataset на Kaggle](https://www.kaggle.com/search?q=license+plate+characters) — искать датасеты с отдельными символами номеров
- **Синтетическая генерация** — рендерить символы разными шрифтами (Highway Gothic, FE-Schrift, Charles Wright) с аугментацией (шум, поворот, яркость)

**Рекомендуемый объём:** 1000-5000 изображений на класс (36 классов = 36k-180k изображений)

**Формат:** папки по классам (ImageFolder структура PyTorch)
```
dataset/
  train/
    0/ [img1.png, img2.png, ...]
    1/ [...]
    ...
    Z/ [...]
  val/
    ...
```

## Шаг 3: CharacterClassifier (CNN)

**Файл:** `app/character_classifier.py`

**Архитектура:** лёгкая CNN, не нужно ничего тяжёлого — задача простая (32x32 grayscale → 36 классов)

```
Input: 32x32x1 (grayscale)
Conv2d(1, 32, 3) → ReLU → MaxPool(2)   # 16x16x32
Conv2d(32, 64, 3) → ReLU → MaxPool(2)  # 8x8x64
Conv2d(64, 128, 3) → ReLU → MaxPool(2) # 4x4x128 (или 3x3)
Flatten
Linear(128*x*x, 256) → ReLU → Dropout(0.5)
Linear(256, 36)
Softmax
```

**Обучение:**
- Framework: PyTorch (уже есть в окружении через Ultralytics)
- Оптимизатор: Adam, lr=0.001
- Loss: CrossEntropyLoss
- Эпох: 20-30 (задача несложная, сойдётся быстро)
- Аугментация: RandomRotation(±5°), RandomBrightness, GaussianNoise
- Целевая accuracy на val: >95%

**Экспорт:** сохранить в ONNX для быстрого инференса (совместимо с текущим стеком)

## Шаг 4: Интеграция в пайплайн

Заменить `PlateReader` (текущий класс с RapidOCR) на новый `PlateReader` который использует `CharacterSegmentor` + `CharacterClassifier`:

```python
class PlateReader:
    def __init__(self, preprocessor, segmentor, classifier):
        self.preprocessor = preprocessor
        self.segmentor = segmentor
        self.classifier = classifier

    def read_plate(self, image):
        processed = self.preprocessor.process(image)
        char_crops = self.segmentor.segment(processed)
        if not char_crops:
            return None, None
        predictions = [self.classifier.predict(crop) for crop in char_crops]
        # predictions = [('A', 0.98), ('W', 0.95), ...]
        text = "".join(char for char, conf in predictions)
        avg_conf = sum(conf for _, conf in predictions) / len(predictions)
        return text, self._get_confidence_level(avg_conf)
```

## Метрики успеха

| Метрика | Текущий результат | Целевой результат |
|---------|------------------|-------------------|
| Точность на тестовых кейсах | ~60-65% (4/6 частично) | >85% |
| Стабильность на видео (один номер = один результат) | нестабильно | стабильно |
| Галлюцинации | есть | отсутствуют |
| Скорость инференса | ~25ms (RapidOCR) | <20ms (лёгкая CNN) |

## Риски

| Риск | Вероятность | Митигация |
|------|------------|-----------|
| Сегментор плохо работает на наклонных номерах | средняя | deskew уже есть в пайплайне, плюс можно добавить horizontal projection correction |
| Слипшиеся символы после дилатации | средняя | тюнинг kernel size дилатации, watershed алгоритм как запасной вариант |
| Недостаточно данных для CNN | низкая | синтетическая генерация покрывает пробелы |
| CNN путает похожие символы (0/O, 1/I) | средняя | взвешенная loss функция, больше примеров граничных случаев |
